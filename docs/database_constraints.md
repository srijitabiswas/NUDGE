# NUDGE Database Constraints & Relationship Architecture
**Phase 7: Database & Data Layer — Step 44**
**Contract Reference:** `PROJECT.md` — Shared Structured JSON / Data Contract (Step 3)
**Schema Implementation:** `backend/database/schema.sql` (Step 43)

---

## 1. Overview

Step 44 formalizes the relational integrity rules, primary keys, foreign key assessments, domain constraints, default behaviors, and indexing strategies governing the NUDGE database. The goal is to enforce the 19-field shared data contract at the database engine level while maintaining strict runtime compatibility with the NLP, OCR, and ML modules.

---

## 2. Primary Key Specification

* **Column**: `task_id INTEGER PRIMARY KEY AUTOINCREMENT`
* **Ownership**: Task / Storage Layer
* **Rationale & Mechanics**:
  * Serves as the immutable unique identifier for every task record.
  * In SQLite, `INTEGER PRIMARY KEY AUTOINCREMENT` guarantees unique sequential 64-bit integer keys that are never reused, even after deletions.
  * Directly satisfies downstream expectations:
    * `ml/priority_engine.py` expects an integer/string identifier (`task["task_id"]`).
    * `frontend/src/services/taskAdapter.js` maps `id: task.task_id`.
    * Newly extracted payloads from NLP enter the storage layer with `"task_id": null`; the storage layer generates and returns the populated ID upon persistence.

---

## 3. Foreign Key Assessment for Phase 7 Scope

* **Current Finding**: **No foreign keys are defined or required in the current Phase 7 scope.**
* **Architectural Rationale**:
  1. **Single Core Entity (`tasks`)**: The primary deliverable of Phase 1 / Phase 7 is the end-to-end task pipeline (NLP/OCR $\rightarrow$ Structured Task $\rightarrow$ Storage $\rightarrow$ Intelligence $\rightarrow$ Dashboard $\rightarrow$ Alerts). All 19 contract fields directly belong to the task entity.
  2. **Array Preservation for `change_information`**: Rather than creating a separate child table (`task_changes`) with a foreign key back to `tasks`, change records are stored as a JSON-validated array (`TEXT NOT NULL DEFAULT '[]'`). This avoids relational join complexity, eliminates relational impedance mismatch, and directly preserves the exact contract shape (`"change_information": []`) expected by both NLP output and the frontend dashboard.
  3. **No Premature Lookup Tables**: Introducing lookup tables for `subjects`, `sources`, or `task_types` would invent entities not approved in `PROJECT.md` and create brittle foreign key dependencies across modules.
  4. **No Authentication / Multi-Tenancy in Phase 1 Critical Path**: User accounts and authentication tables are not part of the initial data pipeline scope.
* **Future Evolution**: If future phases introduce user multi-tenancy (`users` table) or split changes into normalized audit logs, SQLite foreign key enforcement (`PRAGMA foreign_keys = ON;`) will be enabled with `REFERENCES tasks(task_id) ON DELETE CASCADE`.

## 4. Integrity Constraints Matrix

The schema enforces strict domain validation and nullability rules via SQLite column constraints and table-level `CHECK` clauses:

| Column | Nullability | Constraint Expression | Rationale & Behavioral Rule |
|---|---|---|---|
| `task_id` | NOT NULL (PK) | `PRIMARY KEY AUTOINCREMENT` | Unique task identifier generated by storage. |
| `task_title` | NOT NULL | `CHECK (length(trim(task_title)) > 0)` | Disallows empty strings or whitespace-only titles from NLP. |
| `description` | Nullable | None | Optional context/instructions. Must preserve `NULL` if absent. |
| `task_type` | Nullable | `CHECK (task_type IS NULL OR length(trim(task_type)) > 0)` | Disallows empty classification strings. |
| `subject` | Nullable | None | Optional academic course identifier. Preserves `NULL` if absent. |
| `due_date` | Nullable | None | Raw date string (`YYYY-MM-DD`). Preserves `NULL` if no date in text. |
| `due_time` | Nullable | None | Raw time string (`HH:MM`). Preserves `NULL` if no time in text. |
| `due_datetime` | Nullable | None | Normalized ISO 8601 (`YYYY-MM-DDTHH:MM:SS`). Populated **only** when both date and time exist. Must remain `NULL` if `due_time` is missing. |
| `event_datetime` | Nullable | None | Scheduled event datetime (`YYYY-MM-DDTHH:MM:SS`). Preserves `NULL` if not an event. |
| `date_time_expression`| Nullable | None | Literal phrase from message. Preserves `NULL` if absent. |
| `status` | NOT NULL | `CHECK (status IN ('pending', 'in_progress', 'completed', 'cancelled'))` | Restricts lifecycle state to the four states recognized across ML and frontend. Authoritative storage control. |
| `importance` | Nullable | None | Preserves `NULL` when unstated. Supports ML string values (`'high'`, `'medium'`, `'low'`). |
| `estimated_effort` | Nullable | `CHECK (estimated_effort IS NULL OR estimated_effort >= 0)` | Disallows negative numbers. Preserves `NULL` when unknown (missing effort $\neq$ zero effort). |
| `source` | NOT NULL | `CHECK (length(trim(source)) > 0)` | Provenance tracking (e.g. `'LMS Notice'`, `'Email'`). Cannot be blank. |
| `raw_text` | NOT NULL | `CHECK (length(trim(raw_text)) > 0)` | Original message text for auditing and reprocessing. Cannot be blank. |
| `confidence` | NOT NULL | `CHECK (confidence >= 0.0 AND confidence <= 1.0)` | Bounds NLP extraction confidence to a valid probability range [0.0, 1.0]. |
| `change_information` | NOT NULL | `CHECK (json_valid(change_information) AND json_type(change_information) = 'array')` | Enforces valid JSON syntax and guarantees the top-level structure is an array. Rejects objects, literals, or malformed strings. |
| `created_at` | NOT NULL | None | Automatic generation on insert. Never `NULL`. |
| `completed_at` | Nullable | None | Recorded when status becomes `'completed'`; cleared to `NULL` if task is reopened. |

## 5. Defaults & Temporal Conventions

* **`status` Default**: `'pending'` (explicit requirement from `PROJECT.md`).
* **`confidence` Default**: `0.0` (baseline fallback).
* **`change_information` Default**: `'[]'` (empty array when no change is detected).
* **`created_at` Default**: `strftime('%Y-%m-%dT%H:%M:%S', 'now', 'localtime')`.
* **Timestamp Format Standard**:
  * Standardized as **naive local ISO 8601 strings: `YYYY-MM-DDTHH:MM:SS`**.
  * Matches Python `datetime.now().isoformat()` and avoids timezone mismatch exceptions in `ml/priority_engine.py` and `ml/intelligence_metrics.py`.

---

## 6. Indexing Strategy

Four targeted B-Tree indexes are defined to optimize queries without incurring excessive write overhead:

1. **`idx_tasks_status`** on `tasks(status)`:
   * Optimizes filtering active tasks (`status IN ('pending', 'in_progress')`) for the student dashboard, priority recommendations, and early risk detection.
2. **`idx_tasks_due_datetime`** on `tasks(due_datetime)`:
   * Accelerates deadline sorting, overdue calculations, and upcoming deadline queries within 24 hours or 7 days.
3. **`idx_tasks_event_datetime`** on `tasks(event_datetime)`:
   * Optimizes schedule/calendar rendering for exams, lectures, and meetings.
4. **`idx_tasks_subject`** on `tasks(subject)`:
   * Enables fast course-wise filtering for the Academics dashboard view.

---

## 7. Consistency with PROJECT.md Shared Data Contract

The constraint architecture strictly satisfies all Step 3 rules:
* **Missing Data Preservation**: Missing fields store native SQL `NULL`, preventing fabricated dates, times, or statuses.
* **Separation of Concerns**: Intelligence signals (`priority_score`, `risk_level`) are excluded from table constraints, maintaining pure dynamic computation.
* **Status Authority**: Storage layer alone governs transitions through the valid domain.
